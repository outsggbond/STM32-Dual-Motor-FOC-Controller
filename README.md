# STM32_2_motor

基于 STM32CubeMX 生成的 STM32F103C8T6 **双电机 FOC 控制**工程。

外设（GPIO / I2C / TIM / USART）由 CubeMX 初始化；电机业务代码全部在 `Core/` 下的独立模块里。
当前硬件**没有 ADC 电流采样**，所以是**电压模式 FOC**：AS5600 位置反馈 → 位置/速度环 → 电压矢量 → SVPWM → 三相 PWM。
位置环与速度环均已在硬件上实测通过（见下方「验证状态」）。

> **只是要操作这台机器（上电、发命令、读遥测）请看 [`MANUAL.md`](MANUAL.md)** —— 那份是给操作者的，
> 包含安全边界与故障排查。本文件是给读代码、改代码的人看的。

## 硬件平台

| 项 | 值 |
|---|---|
| MCU | STM32F103C8T6（Cortex-M3，Blue Pill，LQFP48，**无 FPU**，软浮点） |
| 系统时钟 | HSE 8 MHz × PLL9 = **72 MHz** |
| 总线时钟 | AHB 72 MHz / APB1 36 MHz / APB2 72 MHz，定时器时钟 72 MHz |
| 工具链 | STM32CubeIDE（GCC），HAL 库 |
| 固件包 | STM32Cube FW_F1 V1.8.7（CubeMX 6.18.1） |
| 电机 | 2804 云台电机，7 极对数，额定 12 V，编码器 AS5600（12 位单圈绝对式） |

## 软件模块

| 文件 | 职责 |
|---|---|
| `main.c` | 外设初始化 → `Motor_System_Init()` → 启动 TIM3 → `while(1)` 跑 `Motor_System_Task()` |
| `motor.h` / `motor.c` | `Motor_t` 对象、PWM、EN、状态迁移、故障入口 |
| `motor_config.h` | 两个电机的硬件映射、极对数、编码器方向、限幅、出厂 PID 增益 |
| `motor_control.h` / `.c` | 状态机、编码器更新、电角度、零位校准、速度/位置环、FOC 输出、堵转与热保护 |
| `foc.h` / `foc.c` | Clarke / Park / 逆 Park / SVPWM |
| `pid.h` / `pid.c` | 通用 PID（积分限幅 + 反算抗饱和） |
| `as5600.h` / `as5600.c` | AS5600 I2C 驱动 |
| `uart_debug.h` / `.c` | 串口命令解析、状态上报、帮助 |

数据流：`AS5600 → 机械角 → 电角度 → 位置/速度环 → Vq（Vd=0）→ 逆Park → SVPWM → TIMx CCR`。
`timer.c / gpio.c / i2c.c / usart.c / stm32f1xx_it.c` 继续由 CubeMX 管理。

## 关键说明

- **双电机独立**：`motor1` / `motor2` 是两个完全独立的 `Motor_t` 对象，各自的硬件、目标、PID、
  校准状态、堵转/热保护状态全部独立。**不存在一个电机修改另一个电机参数的情况**——
  这类共享曾经是本工程的一类主要 bug（文件级 static 变量），现已全部收进结构体。
- **"独立"只到电气为止**：两台**共用同一条 12 V 母线**，所以固件上互不干涉、电气上不独立 ——
  一台的电流突变会通过母线压降影响另一台。低电压小电流时看不出来，大负载同时启动时会。
  要真正独立需要两路独立电源。热也是共享的（同一个壳/环境）。
- **一行命令只能管一台电机**：`UART_Debug_Parse` 用 `M1`/`M2` 前缀选电机，
  没有"同时设置两台"的语法（`M1 SPD 5 M2 SPD 5` 无效）。全局命令只有两个：
  `STOPALL`（停两台）和 `STATUS`（打两台）。
- **实时性**：TIM3 中断（1 kHz）里执行两个电机的 FOC 计算；`while(1)` 只做串口与编码器采样，
  不参与实时控制。编码器读取被节流到 1 ms，避免阻塞式 I2C 拖垮主循环。
- **编码器方向**（`MOTORn_ENCODER_SIGN`）：AS5600 的计数正方向由磁铁装向决定，与换相正方向
  不一定一致。**两个电机实测需要相反的符号**（电机1 `+1`、电机2 `-1`），必须逐台实测，
  不能互相复制——复制错的后果不是报错，而是"换相正确、测速反向"的速度环正反馈，
  一发 `SPD`/`ALIGN` 就飞车。复测方法：`M1 OLTEST 2 2`，`STATUS` 里 `ANGLE` 必须**增大**。
- **换相基准 ≠ 位置零点**：`zero_angle`（换相基准，`θe = direction × pole_pairs × (θm − zero_angle)`）
  与 `position_offset`（位置环零点，`POS <度>` 以它为原点）是**两个独立变量**，曾经共用一个，
  于是 `M1 ZERO` 顺手把换相基准写成了当前转子位置 —— 转子并不在 d 轴对齐点上，电角度凭空偏
  7×δ，实测 `TARGET=+1.00` 而电机以约 **−10 rad/s 反向飞车**。现已拆分：`zero_angle` 只由校准
  写入、任何用户命令都不碰；`position_offset` 在校准时随 `zero_angle` 一起初始化（保证 `POS`
  语义与拆分前一致），之后仅 `ZERO` 命令可改。
- **三道安全闸**（电压模式没有电流采样，固件不知道电流多大，只能限压+限时）：
  速度环输出硬上限 `MOTOR_VEL_VOLT_LIMIT`（**6.6 V** = 0.55×母线，SVPWM 线性区上限是
  母线/√3 = 6.93 V）、堵转检测 `MOTOR_STALL_*`、热累积 `MOTOR_THERMAL_*`。
  请勿随意放宽，依据见 `motor_config.h` 顶部注释。
- **修改约定**：在 CubeMX 中重新生成代码时，仅 `USER CODE BEGIN/END` 区块内会被保留；
  电机业务代码放在独立模块里，不受重新生成影响。**改动头文件里的结构体后必须 `make clean`**
  （增量编译会把旧 `.o` 与新的结构体偏移量链在一起）。
- **上电自动转动**：`motor_config.h` 里的 `MOTORn_AUTO_SPIN_TARGET_VEL` 目前为 `0.0f`。
  排查接线/量电压期间必须保持 `0.0f`，否则一上电电机就会通电。

## 串口命令

115200 8N1，命令以 `\r` 或 `\n` 结尾，`M1` / `M2` 选择电机。**一行只能给一台电机下命令** ——
不要用 `;` 把多条串起来：两台同时发遥测时串口会偶发截断，串在一起的命令可能整条被当成
无法解析的输入（实测 `M2 KP 0.1; M2 SPD 5` 变成一串帮助文本）。一条一条发，中间留间隔。

| 命令 | 说明 |
|---|---|
| `M1/M2 START` / `STOP` | 使能 / 停机（PWM 归零、EN 关断） |
| `M1/M2 SPD <rad/s>` | 速度环目标角速度 |
| `M1/M2 POS <度>` | 位置环目标角度（相对**位置环零点** `position_offset`） |
| `M1/M2 VOL <V>` | 开环固定电压（调试用） |
| `M1/M2 VEL <kp> <ki> <kd>` | 一次设置速度环三增益（`kp` 有安全上限） |
| `M1/M2 KP` / `KI` / `LIMIT <V>` | 单项设置 |
| `M1/M2 STATUS` | 单机状态；`STATUS` 为双机一起打印 |
| `M1/M2 ZERO` / `CLR` | 把当前位置设为位置环零点（只影响 `POS`，不影响换相）/ 清除故障锁存 |
| `M1/M2 CALSPIN [V] [rad/s]` | 旋转式零位校准（拖起来→减速对齐→记录基准） |
| `M1/M2 DIR [1\|-1]` / `ENP 0\|1` | 换相方向 / EN 有效极性 |
| `M1/M2 OLTEST <电角速度> <V>` | 开环强拖，绕开编码器与闭环 |
| `M1/M2 RAMP <V> <电角速度> <ms>` | 电压软启动斜坡 |
| `M1/M2 ALIGN <目标rad/s> [V] [秒]` | 开环拖动→闭环速度交接启动 |
| `M1/M2 GUARD 0\|1` | 堵转保护开关 |
| `STOPALL` / `HELP` | 双机紧急停机 / 帮助 |

`STATUS` 输出形如：

```
M1 STATE=RUNNING ANGLE=350.77 EANGLE=270.00 VEL=1.00 TARGET=1.00 PWM=0.50,0.50,0.50 ERR=0 VTRV=9.11
```

`PWM=0.50,0.50,0.50` 表示零差模电压。`VTRV` 是上次校准自检的带符号行程（弧度）。

**双机同时运行时遥测会翻倍**（两台都 `RUNNING` 时每 500 ms 打两行），串口偶发**截断行**
（实测 40 多条里出现 2 条，如 `TARGET=1`、`ERR=` 后面断掉）。这是**遥测链路**的问题，
不是控制问题 —— 电机本身照常运行。**写解析脚本时不能假设每行完整**：遇到截断行跳过并重读，
不要把它当成错误状态。

## 验证状态（2026-10-02，实机）

| 项 | 结果 |
|---|---|
| 编码器方向 | 两台分别实测（电机1 `+1`、电机2 `-1`），`OLTEST` 下 `ANGLE` 均递增 |
| 速度环冷启动 | `START` + `SPD 1` 从静止直接起转，无需 `ALIGN` |
| 速度环稳态 | 目标 1 → 实测 0.996～1.010 rad/s；目标 3 → 3.008；反向 0 次 |
| 双机同时 | M1=2、M2=4 rad/s 同时运行，实测 2.001 / 4.001，互不干扰 |
| 双机同时（不同目标 + 中途反向） | M1=+8、M2=+15 同时运行（实测 ≈7.9 / ≈15.1）；再把 **M1 反转到 −8**，M2 仍稳在 13.4~16.4 **完全不受扰动**。回归脚本 `Debug/dualtest.ps1` |
| 位置环 | 双机不同目标同时运行，稳态误差 **0.000°**，`EANGLE` 与 7×目标 mod 360 自洽 |
| 出厂增益 | `kp=0.05`、`ki=0.5`（整定依据见 `motor_config.h` 的 `MOTORn_VEL_KI` 注释） |
| `ZERO` 不再破坏换相 | 两台分别回归：`ZERO` 后 `SPD 1` 实测 1.006 / 0.996 rad/s、反向 0 次（修复前电机1 为 −10.7 rad/s 飞车） |
| `ZERO`/`POS` 语义 | 两台：`ZERO` 后 `POS 0` 原地不动；`POS 90`/`POS 45` 精确步进（误差 0.00°）；`EANGLE` 在 `ZERO` 前后不变 |
| 位置精度 | 两台各走 0/45/90/135/180/270/315°，误差 **0.00°**；270° 处两台各差 1 个编码器计数（±0.09°，= 0.088°） |
| 速度范围 | 0.5 → 50 rad/s 双向线性（正反各测，均值误差 <0.2%） |
| 速度上限（6.6 V 限幅，两台分别实测） | 电机1：3.0 V→55.8、4.0→60.4、5.0→63.3、**6.6→67.3 rad/s**；电机2：4.0→56.8、**6.6→62.8 rad/s** |
| 上限为何只到这里 | 边际增益从 4.6 掉到 **2.5 rad/s/V**，是**反电动势**在限，不是限幅在限（6.6 V 时占空比已到 0.04/0.96 = 调制比 0.95，确实饱和）。再快需要提高母线电压——那是硬件/耐压决定，不是调参能解决的 |
| 低速下限 | ≲1 rad/s 时 `ripple` 升到 ~0.9（静摩擦死区的黏滑），1 rad/s 以上 ripple ≤0.2 |
| 低速增益边界 | `kp` 只能到 0.1 **且只在 ≲1 rad/s 可用**：`kp=0.1` 在 5 rad/s 时固件 `VEL` span 达 110、20 rad/s 时 87（极限环）。`ki>0.5` 在所有测过的速度都不稳。出厂仍为 `kp=0.05 / ki=0.5` |
| 静摩擦前馈 | **实测无效，默认已改 0**：目标 0.5 rad/s 下 FF 0/0.3/0.6/1.0/1.5 V 的均值与 sd 完全不变。原因是前馈加在 PI 环**外面**，积分器会抵消任何常量偏置。真因是静摩擦≫动摩擦的迟滞，常量前馈补不了 |
| 双机同时 | M1=10、M2=25 rad/s 同时运行，实测 10.001 / 24.980（固件 `VEL` span 2.45 / 2.80） |
| 电压裕度 | 6.6 V 限幅 = 相电压幅值 6.6 V = **额定 12 V 的 55%**；SVPWM 线性区上限是母线/√3 = 6.93 V，代码夹在 6.6 V（0.55×母线） |

## 调试量尺（`Debug/`）

不要靠肉眼读 `VEL` 字段判好坏——它每 500 ms 才刷新一次，且量化步长 0.19 rad/s。这些脚本把
串口行按**到达时刻**打戳再处理：

| 脚本 | 用途 |
|---|---|
| `velstat.ps1 -Motor n [-Setup "M1 START; M1 SPD 5"]` | 测速：逐行微分 `ANGLE`，输出 `mean/min/max/sd/ripple/reversals`，并打印固件 `VEL` 的 `min/max/sd/span` + 极限环告警 |
| `posstat.ps1 -Motor n [-Targets "0,45,90"]` | 测角：判停→`POS 0` 切位置环→`ZERO` 钉住原点，再逐点步进，输出每点稳态角与残差 |
| `dualtest.ps1 [-Speed1 8] [-Speed2 15]` | 双机同时回归：两台不同目标同时跑，再把 M1 反向，验证 M2 不受扰动 |

- `ripple`（峰峰值/均值）<0.5 平滑，>1.5 是黏滑。
- **`velstat.ps1` 的微分必须做「连续性解卷绕」**：遥测是**稳定 500 ms 一行**，目标 10 rad/s 时
  两行之间转子已转过 286°，盲目按 ±180° 折叠会得到**符号相反**的干净数据（曾把 +10.18 报成
  −2.57，sd 0.03、零反向，看起来完全不像噪声）。现在用固件自己的 `VEL` 作分支参考来解卷绕，
  并在拟合值与参考值相差超过半条 360° 分支时打印 `WARNING`。自己写解析脚本时务必照做。
- `posstat.ps1` 采原点前要先**判停**，而且判停只能用 `ANGLE`：
  **`VEL` 和 `EANGLE` 在 `READY` 下是冻结的陈旧值** —— `Motor_UpdateVelocity()` /
  `Motor_UpdateAngle()` 只在 `MOTOR_STATE_RUNNING` 分支里调用（`motor_control.c`），
  `READY` 分支只写 `PWM=0`。实测停机后 `VEL` 会一直停在 26.84 不动，而 `ANGLE`
  （由后台任务里的 `Motor_ReadEncoder()` 刷新，**不受状态限制**）真的在动：
  停机后 306.9° → 48.1°，约 0.6 s 内到静止。用 `VEL` 判停会得到一个永远不成立的
  条件（曾因此报 "ROTOR STILL COASTING after 10s"）。
- `posstat.ps1` 采原点前还必须**先把电机切进位置环**（脚本里发 `POS 0`）：
  `ZERO` 只改 `position_offset`/`target_angle`，**不改 `control_mode`**。紧接一个
  速度测试之后运行本脚本时，电机还留在 `VELOCITY` 模式、目标 25 rad/s，`START`
  会把它直接拉回 25 rad/s 转起来，两次原点读数永远不一致 —— 这才是旧版报
  "NO TELEMETRY" 的真正原因（与滑行无关）。

## 使用

1. 用 STM32CubeIDE 导入本工程（或打开 `STM32_2_motor.ioc` 重新生成）。
2. 编译烧录：也可在命令行构建 —— 把 CubeIDE 的两个 `tools\bin`（gcc 与 make）加进 `PATH`，
   在 `Debug/` 下 `make -j4 all`；用 `STM32_Programmer_CLI -c port=SWD -w Debug\STM32_2_motor.elf -v -rst` 烧录。
3. 串口 115200 8N1，发 `HELP` 看命令表，发 `M1 SPD 1` 让电机 1 以 1 rad/s 旋转。
   本机实测用的 COM4 **不是 ST-Link 的 VCP**，而是独立的 CH340 USB-TTL 适配器接到板子
   UART 上——它与 SWD 链路无关，所以「串口有回应」并不能说明调试器是活的，反之亦然。
