# STM32 双电机 FOC —— 使用说明

适用固件：build #5（`-O0`，63072 / 65536 字节）
最后更新：2026-10-03
适用板卡：STM32F103C8T6 + 两个 2804 云台电机 + 两个 AS5600 磁编码器

> 本手册里的数字**都是实测的**，不是理论值。凡是"实测"字样，都是在 2026-10-03
> 的 64 项测试套件（`Debug/suite.ps1`）或专门探针里真实量出来的。
> 命令列表的权威来源是 `Debug/HELP.txt`；本手册补充的是**语义和陷阱**。

## 1. 硬件与接线

| 项 | 值 |
|---|---|
| 主控 | STM32F103C8T6，72 MHz，64 KB flash |
| 电机 | 两个 2804 云台电机，**12 V 额定，20 V 仅瞬时**，极对数 7.0 |
| 母线 | 12 V |
| 输出电压上限 | **6.6 V**（0.55 × 12 V），硬夹取 |
| 编码器 | AS5600，12 位 = 4096 计数/圈，**1 计数 = 0.088°** |
| 编码器总线 | **两条独立 I2C**，各 100 kHz |
| 控制环 | TIM3，**1 kHz** |
| PWM | TIM1（M1）/ TIM2（M2），20 kHz |
| 串口 | USART1，PB6/PB7，**115200 8N1** |

### ★ 串口是 COM4，但**不是** ST-Link 的虚拟串口

COM4 枚举为 `USB-SERIAL CH340`（wch.cn），是一个独立的 USB-TTL 小板接到板子的 UART 上。

**它和 SWD 完全无关** —— 所以"串口能回话"**不能**证明调试器活着，反过来也一样。别用一个去诊断另一个。

### 怎么用电脑连上板子发命令

**串口参数（就这四个）：**

| 项 | 值 |
|---|---|
| 端口 | `COM4`（以设备管理器实际枚举为准，插拔可能变号） |
| 波特率 | `115200` |
| 帧格式 | **8N1**（8 数据位 / 无校验 / 1 停止位） |
| 流控 | **无**（None） |

**★ 发送必须以 `\r\n`（CRLF）结尾。** 只发 `\n` 固件不认，会当没收到。

**现成的客户端就是那些 `.ps1`** —— 不想自己写就用现成的：

```
Debug\suite.ps1                 完整 64 项
Debug\velstat.ps1 -Cmd "M1 SPD 5"    速度统计（注意要带 M1 前缀）
```

**想手动发一条，PowerShell 五行就够：**

```powershell
$port = New-Object System.IO.Ports.SerialPort "COM4",115200,`
    ([System.IO.Ports.Parity]::None),8,([System.IO.Ports.StopBits]::One)
$port.Encoding = [System.Text.Encoding]::UTF8     # ★ 见下
$port.ReadTimeout = 50
$port.Open(); Start-Sleep -Milliseconds 300; $port.DiscardInBuffer()
$port.Write("M1 STATUS`r`n"); Start-Sleep -Milliseconds 300
$txt = $port.ReadExisting(); $port.Close(); $txt
```

**★★ 那个 `$port.Encoding` 必须设成 UTF8。** 板子回的是 UTF-8（`未知命令`、`OK STOPALL: 两个电机已停机`），
而 .NET `SerialPort` 的**默认编码是 ASCII** —— 不设的话中文全部变 `?`，你会以为命令发错了。

**两个会让人误判的行为：**

1. **RUNNING 时板子会主动刷遥测，READY 时完全安静。**
   所以"READY 状态下只能收到一行"是正常的，别去找丢失的帧。
2. **最后一行可能是"收到一半"的帧。** 运行中读窗口，末尾常常是
   `M1 STATE=RUNNING ANGLE=.. VEL=..` 断在 `ERR=` 之前 —— **任何字段都要从一条完整的帧里取**
   （脚本里用 `Motor-Frame` + `Frame-Str`/`Frame-Field`）。这是套件里踩过的真坑，详见 §10。

**用现成串口助手（PuTTY / 串口调试助手）也行**，同样四个参数 + 发送末尾加 CRLF + 接收设 UTF-8。

> 回复长度上限：最长一条 220 字节，发送环形缓冲 3072 字节，**不会截断**。

### 上电行为（必须知道）

**每次上电，两个电机都会自己动一下。** 这是开机换相校准（CALSPIN），在收到任何命令之前就发生。属正常，不是 bug。

## 2. 开机流程（照这个顺序做）

```
1. 上电，等电机自己转完校准（约 1~2 秒）
2. 读一次自检结果：   M1 STATUS      （非易失）
                     M2 STATUS
3. 检查两件事：
   - ERR=0
   - VTRV 是一个合理的非零值
4. 确认转子已静止（见下面的"回零"）
5. 需要定位就先 ZERO，再 POS
```

### ★ VTRV 是"开机自检行程"，**不是**母线电压

`VTRV` 是**上电校准那次**测到的带符号行程（正常上电后 M1 ≈ 9.23 / M2 ≈ 9.05），之后**冻结**，不再更新。

- 它**不是**实时电压，别看它判断供电。
- **只有刚上电时可信。** 如果一次重新校准被中途打断，`VTRV` 会停在 **0.00 而且 `ERR=0`** —— 静默地告诉你一个坏掉的基准。
- 所以 `VTRV≈0` 且你刚上过电 = 那次校准没成功，**重来**。

## 3. 命令参考

先看 `Debug/HELP.txt`（那是权威列表）。下面只补 **HELP 里没写、但会咬人** 的语义。

### 3.1 速度

| 命令 | 说明 |
|---|---|
| `M1 SPD <rad/s>` | 速度环。**可用区间约 0.5 ~ 58 rad/s** —— 再往上被 6.6 V 夹住，是电压限的，不是目标限的（实测：目标 200 → 均值 53.8，峰值 57.9） |
| `M1 SPD 0` | **通电零矢量**，PWM = `0.50,0.50,0.50`，有制动感 |
| `M1 STOP` | **停机自由滑行**，PWM = `0.00,0.00,0.00`，**没有保持力矩** |

**★ `STOP` 和 `SPD 0` 不是一回事。** 要"停住"用 `SPD 0`；`STOP` 是断电让转子自己滑。

**★ 0.5 rad/s 以下不要指望稳定调速。** 那是摩擦死区，表现是走走停停的 stick-slip，不是转速波动。

### 3.2 位置

| 命令 | 说明 |
|---|---|
| `M1 POS <度>` | 位置环。相对于**位置环零点**（默认 = 校准零点） |
| `M1 ZERO` | 把**当前位置**设为位置环零点。只影响 POS，不影响换相 |

**实测的位置性能：**

| | 值 |
|---|---|
| 分辨率 | 0.088°（1 个编码器计数，这是物理下限） |
| 90° 移动到位 | 约 1 ~ 1.5 s（套件实测 1449 / 1534 / 1535 ms；13 ms 采样的 `posstep.ps1` 能看到最短到 0.95 s） |
| 到位后残差 | 0.03 ~ 0.18° |
| 静止保持漂移 | **0.000°**（8 次采样峰峰值，前提：POS 一直激活） |
| **超调** | **2 ~ 4.5°**，尾巴拖 **1 ~ 3.5 s** |
| 起转延迟 | 约 20 ms |

**★ 位置环是纯 P，没有阻尼。** 所以有超调和长尾巴。想改善，固件里已经有两根杠杆：
**前馈 `FF`**（现在 = 0，那条尾巴主要就是它造成的）和**制动力曲线 `TRAJ`**（实测能把超调砍 30%）。

### 3.3 ★ 回零（ZERO）没有静止检查 —— 这是最容易犯的错

`ZERO` **不管转子在不在动**。在转子还在转的时候发 `ZERO`，会锁存一个**错误的原点**，
后面所有 `POS` 都错，表现是"凭空多转好几圈"式的假超调。

**正确做法：连续两次读 `ANGLE`，数值完全一致，才发 `ZERO`。**

```
M1 STATUS        -> ANGLE=173.67
M1 STATUS        -> ANGLE=173.67     ← 两次一模一样，才安全
M1 ZERO
```

典型的翻车顺序：`SPD → STOP → ZERO → POS`。`STOP` 之后转子还在滑行，这时候 `ZERO` 就锁错了。

### 3.4 状态字段到底是什么意思

| 字段 | 含义 |
|---|---|
| `STATE` | `READY` / `RUNNING` / `ERROR` |
| `ANGLE` | 机械角，**绝对**，会绕圈（0~360） |
| `EANGLE` | 电角度 = 7 × (机械角 − 校准零点)，也是绕圈的 |
| `TARGET` | 当前目标角。**可以超过 360**（例如 474.02），多圈定位是支持的 |
| `VEL` | 角速度。**见下面的警告** |
| `PWM` | 三相占空比。`0.50,0.50,0.50` = 通电零矢量，`0.00,0.00,0.00` = 断电 |
| `ERR` | 故障位（见 §5） |
| `VTRV` | 开机自检行程，**冻结**（见 §2） |
| `VREF` | 当前速度环输出参考电压 |

**★★ 三个测量陷阱：**

1. **`STATE=READY` 不代表"已到位"。** 它只表示"没在闭环运行"。
   到位必须看 `ANGLE` 和 `TARGET` 的差。而且"到位"本身是**单帧事件**，不是持续状态。
2. **`VEL` 是一个 8 ms 固定窗口的差分**，不是滤波估计。
   - 帧间跳动 **0.6~1.9 rad/s 是正常的**，不代表环路坏。
   - **相邻帧高度相关**：速度在 **1~3 秒**尺度上慢漂，所以一个 3 秒窗口里的 8 帧
     **实际只有 1~3 个独立样本**。`n=8` 严重高估了置信度。
   - **要判断速度，必须对均值判断，而且窗口要够长。** 实测（同一测量，只改窗口长度）：
     | 窗口 | 帧数 | M1 均值在多次运行间的散布 |
     |---|---|---|
     | 3 s | n=8 | **6.43 … 8.37** |
     | 6 s | n=15 | 7.80 … 8.02 |
     | 12 s | n=27 | 8.07 … 8.20 |
     真实值是 **8.0~8.1**（两轴并跑也一样）。3 秒窗口会把一台好电机判成 6.43。
3. **在 READY 状态下 `ANGLE` 是活的，但 `VEL` 和 `EANGLE` 是冻结的**（停在最后一次 RUNNING 的值）。
   所以"等 VEL 归零"这个条件**永远等不到**。

### 3.5 两轴并发

两个电机是**完全独立**的：两条 I2C、两个定时器。可以一个定位、一个调速同时跑。

实测 8 rad/s 两轴并跑，各自稳在 **8.0~8.1**，共总线**没有代价**。

**但两轴之间没有任何协同** —— 没有主从、没有同步轨迹。需要协同的活（差速小车那种）得在上位机自己协调。

## 4. 常用场景配方

### 4.1 定点瞄准（指到角度并保持）

```
M1 STATUS / M2 STATUS          ← 确认 ERR=0
（等 ANGLE 两次读数一致）
M1 ZERO
M2 ZERO
M1 POS 30                      ← 方位角
M2 POS 15                      ← 俯仰角
```
- 换目标后等 **1~1.5 s** 再认为到位；实际尾巴可能到 3.5 s。
- 超调会让光点先冲过目标（3 m 处 3° ≈ 16 cm）再退回。
- **要保持住，POS 必须一直是激活的**（别发 STOP）。

### 4.2 双轴调速 / Lissajous 激光图案

```
M1 SPD 2
M2 SPD 3
```
图案周期 `T = 2π / ω`，`ω` = 两转速的最大公约数。整数比 → 闭合图案；无理比 → 一直变。

| M1 | M2 | 比例 | 周期 |
|---|---|---|---|
| 1 | 1.5 | 2:3 | 12.6 s |
| 2 | 3 | 2:3 | 6.3 s |
| 8 | 12 | 2:3 | 1.6 s |
| 3 | 4 | 3:4 | 6.3 s |

**停的时候用 `SPD 0`，不要用 `STOP`** —— `STOP` 会让镜片继续滑，光束失控扫一会儿。

### 4.3 演示前自检（每次上台前跑一遍）

```
STATUS                         ← 两轴 ERR 必须都是 0
M1 STATUS                      ← VTRV 应该是个合理的非零值
M2 STATUS
M1 SPD 2                       ← 让两轴各转一下，确认能动
M2 SPD 2
（等 2 秒）
M1 SPD 0
M2 SPD 0
```

## 5. 故障与错误码

### ERR 位表

| 位 | 值 | 含义 |
|---|---|---|
| I2C | `0x01` | 编码器总线故障 |
| ENCODER | `0x02` | 编码器故障 |
| CALIBRATION | `0x04` | 校准故障 |
| OVERSPEED | `0x08` | 超速 |
| CONTROL | `0x10` | 控制环故障 |
| **STALL** | **`0x20`** | **堵转保护**（最常见） |
| THERMAL | `0x40` | I²t 热保护 |

### 清故障

```
M1 CLR
M2 CLR
```
注意 `CLR` 是**按电机**的 —— 光发 `CLR` 是"未知命令"。

### 堵转保护（ERR=32）

**触发条件**（三个同时满足）：
- 输出电压 > **1.5 V**
- 2 秒窗口内净位移 < **2°**
- 累计行程 < 限值

**这是一条正确的保护** —— 12 V 电机被通直流还不动，就是在当堵转发热。但它有三个副作用要知道：

1. **任何静态 `VOL` 超过 1.5 V，2 秒后必然报 ERR=32。** 这是设计如此，不是 bug。
2. **竖直轴 + 重力负载保持不动时，如果保持电压超过 1.5 V，也会报堵转。** 轻镜片没事（保持不需要电压）；重负载会咬人。
   逃生口是 `M1 GUARD 0`（关掉保护）—— **这个开关还没在硬件上验证过。**
3. 触发后**锁存**，必须 `CLR` 才能恢复。

**触发时间不是固定的 2 秒。** 那 2 秒窗口只要有运动就重置，而 `VOL` 加到一个还在滑行的转子上，得先磁制动 + 拉入对齐：

- 转子已静止：**2027 ms**
- 转子还在滑行：**4200 ~ 4385 ms**

所以**要观察堵转，必须轮询，不能固定 sleep**。

### ★ CLR 与故障粘滞

- `CLR` 会清**记录**，不清**原因**。故障源还在，就会重新触发。
- **`CLR` 现在会一并清掉速度环积分**（2026-10-03 修复）。所以在旧版本里"CLR 之后一发 SPD 就再次跳闸"的毛病没有了。
- **`ERR` 在位粘滞**：故障恢复、电机重新正常转起来之后，`ERR=32` **仍然挂着**，直到显式 `CLR`。所以你会看到"一台转得好好的电机在报故障"。

### ☠️ ERR=2（I2C）可能是**不可恢复**的

I²C 总线恢复重试次数用尽后，会锁存 `ERR=2`，**没有任何软件出口，只能断电**。而且是**静默**的。

现场演示的应对：**备一个电源开关**。

### 热保护（ERR=64）在 6.6 V 下**永远不会触发**

实测：6.6 V 满输出跑 8 秒，I²t 均衡值 **174**，而限值 **512**。差了 3 倍，够不到。
**所以别指望它保护电机** —— 真要靠的是电压上限和别让它堵转。

## 6. 已知坑清单（照抄，别踩）

| # | 坑 | 后果 |
|---|---|---|
| 1 | `STOP` 没有保持力矩，是自由滑行 | 以为停了，其实还在转/滑 |
| 2 | `ZERO` 没有静止检查 | 锁存错误原点，后面定位全错 |
| 3 | `STATE=READY` ≠ 到位 | 误判"到了" |
| 4 | `VEL` 是 8 ms 窗口，帧间相关，慢漂 | 单帧/短窗口读数不可信 |
| 5 | READY 下 `VEL`/`EANGLE` 冻结 | "等 VEL 归零"永远等不到 |
| 6 | `VTRV` 冻结，且打断的标定会留 0.00 + ERR=0 | 静默的错误基准 |
| 7 | `ERR` 恢复后仍粘滞 | 好电机报故障 |
| 8 | `ERR=2` 用尽即永久，只能断电 | 静默死机 |
| 9 | 静态 `VOL` >1.5 V 必触发堵转 | 以为是 bug |
| 10 | 竖直轴重载保持可能触发堵转 | 瞄准功能被保护干掉 |
| 11 | 位置环纯 P，超调 2~4.5°，尾巴 1~3.5 s | 换目标时冲过头 |
| 12 | 0.5 rad/s 以下进摩擦死区 | 低速调速不稳 |
| 13 | **M2 大角度位置移动有未复现的偶发飞车** | 见 §7 |
| 14 | 板子偶发自复位 | 见 §7 |
| 15 | `HELP` / `?` 命令**已删除**（为省 flash） | 上电不再打印命令表，看 `Debug/HELP.txt` |

## 7. 两个未解决的风险

### 7.1 M2 大角度移动偶发飞车（**未复现**）

- **特征**：峰值卡在略低于 **180°**，然后绕着角度回绕点**无限打转**。
- 只出现过一次，之后多轮测试都没复现。
- **规避**：M2 用**速度模式**；或者避免 M2 的大角度位置移动。

### 7.2 板子偶发自复位（电源完整性）

- 以 **~1.65 秒周期**成串发作。
- `RCC_CSR` 报 **PORRSTF**（掉电复位），**不是代码问题**，也**不是** CH340 的 DTR/RTS 拉的。
- 2026-10-03 这次 64 项全程 `RCC_CSR=0`，**没犯**。
- **遇到"莫名其妙行为"先查这个**，再怀疑环路。用 `Debug/catchreset.ps1` / `rstprobe.ps1`。

## 8. 安全

### 激光（做瞄准/图案演示必读）

- 别让光束在**眼睛高度水平**射出。用外壳，或低功率 Class 2。
- **扫得快不会更安全** —— 视网膜看的是脉冲能量，不是停留时间。
- **记住 §4.2 那条**：`STOP` = 自由滑行 = 光束在"停机"之后还会失控扫一会儿。

### 电机

- **12 V 额定，20 V 仅瞬时。** 6.6 V 上限是刻意的（约额定值的 1/3），别去解它。
- 别长时间跑在接近堵转的地方 —— 热保护不会救你（§5）。
- 低速长时间跑没问题（1~8 rad/s 电流很小）。

## 9. 构建与烧录

工具链在 **K:** 盘（不在 C:）。

```
STM32CubeIDE 2.2.0：K:\STM32CubeIDE\STM32CubeIDE_2.2.0\STM32CubeIDE\
```

- 把两个 `tools\bin` 加进 PATH，然后在 `Debug/` 里 `make -j4 all`
- 烧录：`STM32_Programmer_CLI -c port=SWD -w Debug\STM32_2_motor.elf -v`
  （省略 `-rst` 可以烧完保持 halt，不让开机校准立刻跑起来）

**注意事项：**

- **这个 makefile 只产生 `.elf`**，没有 objcopy 步骤。`Debug/` 里的 `.bin`/`.hex` 是 CubeIDE GUI 留下的**过期**文件 —— **烧 `.elf`**。
- **改了头文件里的结构体，必须 `make clean`**，否则增量编译会拿旧的 `.o` 链进去（结构体偏移错位）。
- **SWD 连不上基本是物理问题**（`DEV_CONNECT_ERR`）。拔插 ST-Link 的 USB 通常就好；反复重试 CLI 的不同模式**没用**。

### Flash 预算

```
text 62604 + data 468 = 63072 / 65536      剩 2464 字节
bss 7020 / 20480
```

**★★ 注释不占 flash。** 预处理器在编译器看到之前就把注释全删了。证据：`Core/Src` + `Core/Inc`
源码共 **274716 字节（268 KB）**，是整个 63.7 KB 镜像的 **4.2 倍** —— 如果注释要存，固件根本不可能存在。

**真正吃 flash 的是：** 字符串字面量（中文在 UTF-8 下 3 字节/字）和**代码**。
`HELP` 表本身约 1250 字节，是 6444 字节 `.rodata` 里最大的一块（已删，备份在 `Debug/HELP.txt`）。

**★ RAM 地址会跟着代码动，而且动错了不报错。** `RX_BUF_SIZE` 从 64 改到 128 时，
`uwTick` 从 `0x200014B0` 移到 `0x200015F0`。`suite.ps1` 里硬编码的 `$ADDR_TICK` 于是静默读到 0，
表现为"时钟死了"。**每次重新编译后都要从 `.map` 重新读一遍：**
```
Select-String -Path Debug\STM32_2_motor.map -Pattern '\.bss\.uwTick'
```

### `-O0` → `-O1`：**没动，等用户决定**

`Debug/makefile` 用的是 `-O0`，62 KB 的 `.text` 对一个 Cortex-M3 软浮点固件来说偏大，
`-O1`/`-Og` 能省出好几 KB。

**没有动的原因**：速度和位置的增益都是针对 `-O0` 这份二进制调出来的。
数学是一样的（同样 IEEE 运算，软浮点），所以行为上应该是安全的，但**切换之后要重跑 `velstat.ps1`**。

**这是用户的决定，已被明确保留。**
